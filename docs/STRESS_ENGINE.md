# Evidence Stress Engine

The Stress Engine asks a different question from ordinary hypothesis scoring:

> **What has to fail, disappear, or lose support for the current conclusion to change?**

It operates on the active `LatticeResult` and returns `omni-stress/v1`.

## Current transfer model

The counterfactual engine starts from the active posterior distribution and removes the contribution of selected evidence rows using fixed transfer factors:

```text
support     = 1.55
contradict  = 0.55
neutral     = 1.00
na          = 1.00
```

For removed evidence, the relevant factor is divided back out of the active hypothesis weight and the distribution is renormalized.

This design makes counterfactual runs deterministic and inexpensive. It is a **sensitivity model**, not a fresh inference run from an external model.

## Baseline state

The report records:

- current leader;
- runner-up;
- signed margin;
- Shannon entropy;
- stability score;
- qualitative grade: `fragile`, `sensitive`, `stable`, or `resilient`.

## Leave-one-evidence-out

Every evidence row is removed individually. The engine records:

- counterfactual leader;
- whether the leader changed;
- total-variation posterior shift;
- loss in leader margin;
- an impact score;
- source ids inferred for that evidence;
- coalitional contribution.

This exposes single-point evidence fragility.

## Minimal flip set

The engine searches bounded combinations of high-leverage evidence rows and finds the smallest tested set whose removal changes the leader.

Current bounds:

```text
maximum removal depth   = 4
maximum flip candidates = 14
```

The bound keeps the search predictable in the browser. A missing flip set means no flip was found within the tested search space; it is not a mathematical proof that no larger set can flip the result.

## Source knockout

Evidence is mapped back to collector provenance using:

- explicit source ids on fused facts;
- source name/id matches;
- domain-specific evidence/source rules.

For each source, Omni removes every evidence row associated with that collector and recomputes the decision state.

This is useful for detecting an apparently diverse case whose conclusion is actually concentrated in one source family.

## Coalitional contribution

Single-row removal can miss interactions between evidence rows. Omni therefore estimates each row's contribution to the current leader margin using Shapley-style attribution.

- up to 9 evidence rows: exact subset enumeration;
- above 9 rows: deterministic permutation sampling;
- current sampling count for the larger case: 256 permutations.

The deterministic seed is derived from the evidence labels so repeated runs over the same matrix remain reproducible.

A regression test checks that the summed coalitional contributions match the evidence-driven change in leader margin within tolerance.

## Adversarial robustness frontier

For removal budgets `0..4`, Omni searches the tested high-impact candidate space for the worst signed leader margin reachable within that budget.

Conceptually:

```text
budget 0 → current decision margin
budget 1 → worst margin after one removal
budget 2 → worst margin after up to two removals
...
```

The frontier is expected to be monotonic non-increasing. This invariant is tested.

## Stability score

The current stability score combines:

- baseline margin;
- size of the minimal flip set;
- dominant-source concentration;
- additional caps when one-row or source-knockout fragility is detected.

The score is a product heuristic for decision robustness. It is not calibrated as a probability that the leading hypothesis is true.

## Next-best collection

Collection priorities are generated from:

1. unresolved evidence rows on the current leader/runner-up boundary;
2. explicit gaps from the top competing hypotheses;
3. existing lattice watch requirements.

For unresolved rows, the engine estimates generic information gain from two directional outcomes and uses current entropy to prioritize rows that could better separate the closest hypotheses.

Autopilot consumes this report as one input to its deterministic planner.

## Model-produced lattices

When the active lattice engine is `grok`, Omni labels the Stress result accordingly. The counterfactual posterior percentages are still generated by Omni's fixed evidence transfer function; they are **not** a re-run of the external model.

## What the Stress Engine does not prove

A high stability score means the conclusion is hard to change under the implemented removal model and tested search bounds. It does not prove:

- the evidence is factually correct;
- omitted evidence does not exist;
- sources are independent;
- the transfer factors are a calibrated causal/statistical model;
- the leading hypothesis is objectively true.
